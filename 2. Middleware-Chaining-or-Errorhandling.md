# Explain REST patterns, middleware chaining, or error handling using AI

## REST Patterns

REST is a way to design APIs using HTTP methods and resource-based URLs.

It helps us create a clear and standard structure for communication between React and Express.


## Middleware

- ***Middleware*** is a function that executes between the `client request` and `server response`.
- It is used to process, ***check***, or ***modify*** the `request` before `sending the response`.

### 1. Built-in Middleware (Provided by Express.js)

Express already provides these middleware functions.

```
    app.use(express.json());
    app.use(express.urlencoded({ extended: true }));
    app.use(express.static("public"));
```

### 2. Custom Middleware (Created by Us)

We write our own middleware function.

```
    const logger = (req, res, next) => {
        console.log("Request URL:", req.url);
        next();
    };

    // Register custom middleware
    app.use(logger);
```

### 3. Third-party Middleware (Installed from npm)
Created by external developers.

```
npm install cors morgan helmet
```
```
app.use(cors());
app.use(morgan("dev"));
app.use(helmet());
```
## Middleware Chaining

- **Middleware** chaining means executing `multiple middleware functions one after another`.
- Each middleware can process the `request` and call` next()` to move to the next function.

```

import express from 'express'

const app = express();

// Middleware 1
const logger = (req, res, next) => {
    console.log("1. Logger middleware");
    next();
};

// Middleware 2
const checkAuth = (req, res, next) => {
    console.log("2. Authentication middleware");
    next();
};

// Middleware 3
const validateUser = (req, res, next) => {
    console.log("3. Validation middleware");
    next();
};

// Middleware chaining
app.get( "/users",
    logger,
    checkAuth,
    validateUser,
    (req, res) => {
        res.send("User details");
    }
);

app.listen(3000);

```

### Error Handling

- `Error handling` means ***identifying an error*** and sending a proper response to the client.

- It ***prevents*** the **application from sending confusing error messages** or ***crashing unexpectedly***.


```

const express = require("express");

const app = express();

app.get("/users", (req, res, next) => {

    try {
        throw new Error("Unable to get users");
    } catch (error) {
        next(error);
    }

});

// Error-handling middleware
app.use((err, req, res, next) => {

    console.log(err.message);

    res.status(500).json({
        message: "Something went wrong"
    });

});

app.listen(3000);

```
