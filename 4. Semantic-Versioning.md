## SEMANTIC VERSIONING 

Semantic Versioning is a way to give **version numbers to software**

It helps developers understand what changes were made when a new version is released.

> Example : 1.2.3

```
            Version 1.2.3
                  |
          +-------+-------+
          |       |       |
        MAJOR   MINOR   PATCH
          |       |       |
       1.0.0    1.1.0   1.0.1
          |       |       |
       Breaking  Feature Bug fix
        change    added
```

### MAJOR

- A major version changes when the software has a breaking change. 
- **Older code** may stop working after **this update**.
> Example: 1.0.0 → 2.0.0


### MINOR
- A minor version changes when a **new feature is added**. 
- **Existing features should continue to work**.
> Example: 1.0.0 → 1.1.0


### PATCH

- A patch version changes when a **bug is fixed**. 
- It should not introduce new features or break existing functionality.

> Example: 1.0.0 → 1.0.1


Command

```
# Increase PATCH version
npm version patch

# Increase MINOR version
npm version minor

# Increase MAJOR version
npm version major

```
