### HTTP Response Codes
- HTTP response codes are numbers sent by the server to the client to tell whether a request was **successful** or **not**.

- When a client sends a request to a server, the server processes that request.

- After processing, the server sends a response code to tell the client what happened.

### Types of HTTP Response Codes

```
HTTP RESPONSE CODE CATEGORIES

1. 100–199
   Category: Informational
   Meaning: Information

2. 200–299
   Category: Success
   Meaning: Request successful

3. 300–399
   Category: Redirection
   Meaning: Go somewhere else

4. 400–499
   Category: Client Error
   Meaning: Problem with client request

5. 500–599
   Category: Server Error
   Meaning: Problem with server
```
### A. 1xx – Informational Codes

- The server tells the client that it can **continue sending the request**.
- It is mainly used when the client sends a large request.



### B. 2xx – Success Codes

***1. 200 – OK***

- The request was successful.
- The server sends the requested data back to the client.
- `Example`: You request user details, and the server sends the user information.

***2. 201 – Created***

- The request was successful, and a **new resource was create**d.
- It is commonly used when **creating a new user** or **product**.
- `Example`: You register a new user, and the server creates that user.

***3. 202 – Accepted***

- The server has accepted the request.
- But the server has not completed the work yet.
- `Example`: You upload a video, and the server accepts it for processing.

***4. 204 – No Content***

- The request was successful.
- But the server does not send any response body.
- `Example`: You delete a user successfully, and there is no data to return.


### C. 3xx – Redirection Codes


***1. 301 – Moved Permanently***

- The requested resource has **permanently moved to another URL**.
- The client should use the new URL in future requests.
- `Example`: Your website changes from `old.com` to `new.com`.

***2. 302 – Found***

- The requested resource is **temporarily available** at **another URL**.
- The client is redirected to that temporary URL.
- `Example`: You visit a website, and it temporarily redirects you to another page.

***3. 304 – Not Modified***

- The requested data has not changed since the last time the client received it.
- The client can use its saved or cached data instead of downloading it again.

### D. 4xx – Client Error Codes

***1. 400 – Bad Request***

- The client sends an **incorrect** or **invalid request**.
- The **server cannot understand** or process the request.
- `Example`: You send **invalid JSON** data to the server.

***2. 401 – Unauthorized***

- The client is **not properly authenticated**.
- The client **needs to provide valid login details** or an **authentication token**.
- `Example`: You try to access your profile without logging in.

***3. 403 – Forbidden***

- The ***server understands the request***.
- But the ***server does not allow the client*** to **access that resource**.
- Example: A normal user tries to access an admin page without permission.

***4. 404 – Not Found***

- The requested **resource does not exist**.

- The server cannot find the **requested URL** or data.

`Example`: You request /users/100, but user 100 does not exist.

***5. 405 – Method Not Allowed***

- The requested HTTP method is not supported for that URL.
- `For example`, the API allows GET but does not allow POST.

***6. 409 – Conflict***

- The request conflicts with the current data on the server.

- The server cannot complete the request because of that conflict.

- `Example`: You try to register an email address that is already registered.

***7. 422 – Unprocessable Content***

- The server understands the request format.
- But the data contains validation errors.
- `Example`: You enter an invalid email address during registration.

***8. 429 – Too Many Requests***

- The client sends too many requests in a short time.
- The server temporarily limits the requests.
-`Example`: You click the login button 100 times within a few seconds.

### E. 5xx – Server Error Codes



***1. 500 – Internal Server Error***

- Something **unexpected went wrong inside the server**.
- The server **cannot complete the request** because of an internal problem.
- `Example`: Your Node.js application has an unexpected error.

**2. 501 – Not Implemented**

- The server does not support the requested functionality.
- The server cannot perform that operation.

***3. 502 – Bad Gateway***

- One server receives an invalid response from another server.
- It usually happens when servers communicate with each other.
- `Example`: Your Node.js server gets an invalid response from another API server.

***4. 503 – Service Unavailable***

- The server is temporarily unable to handle requests.
- It may happen because the server is under maintenance or overloaded.
- `Example`: Your website is temporarily unavailable during maintenance.

***5. 504 – Gateway Timeout***

- One server waits for another server to respond.
- But the other server does not respond within the expected time.
- `Example`: Your Node.js server waits for an external API, but that API takes too long.

***5. HTTP Response Codes Syntax in Node.js***
- Now let's see how to use HTTP response codes in Node.js.
- We can use the statusCode property of the response object.

***Syntax***:
```
res.statusCode = 200;
res.end("Success");
```

***Example 1: Using Node.js HTTP module***
```
import http from "http"

const server = http.createServer((req, res) => {

    res.statusCode = 200;

    res.end("Hello, Welcome to Node.js");

});

server.listen(3000, () => {
    console.log("Server running on port 3000");
});
```

***Example 2: Using Express.js***
```
import express from 'express'

const app = express();

app.get("/users", (req, res) => {

    res.status(200).send("Users fetched successfully");

});

app.listen(3000, () => {
    console.log("Server running on port 3000");
});
```
